# 04 · المراجعة والـ CI

[English](04-code-review.md) · **العربية**

## مين بيراجع لمين

**الـ PRs تبعك بيراجعها زميلك، وتبعه بتراجعها إنت** (GitHub ما بيسمح لصاحب الـ PR يوافق على PR تبعه).

على `main` في **حماية خفيفة**، وGitHub بيفرض بس:

1. التغييرات بتوصل لـ `main` **عن طريق PR** (ما في push مباشر)، و
2. **الـ CI أخضر** (job اسمه `check`: lint + typecheck + format + build).

الموافقة **مو** مفروضة من GitHub، لنضل سريعين. بس هي عادتنا: **اعمل merge بعد ما يوافق زميلك**. إذا مو موجود والتعديل صغير ومستعجل، فيك تعمل merge والـ CI أخضر، وخبّره ليشوفه بعدين.

## الـ CI

ملف `.github/workflows/ci.yml` بيشتغل على كل PR وعلى كل push على `main`. بيعمل نفس اللي بيعمله `npm run check` عندك، يعني إذا نجح عندك بينجح بالـ CI.
الـ CI أحمر؟ افتح الـ PR، ثم **Checks**، ثم `check`، واقرأ أول خطوة حمرا.

## المراجعة بـ 3 خطوات: شغّل · جرّب · شيّك

ما لازم تكون خبير. امشِ على هالخطوات كل مرة (تقريباً 10–15 دقيقة).
مع Claude Code أو Codex: `/review-pr 15` بيمشي معك فيها كلها.

### 1. شغّل

```bash
gh pr checkout 15        # بينقلك على فرع الـ PR
npm install              # إذا تغيّر package.json
npm run dev
```

### 2. جرّب

- امشِ على خطوات **How to test** المكتوبة بالـ PR.
- وبعدين حاول "تكسّره" شوي:
  - اعمل refresh للصفحة
  - صغّر الشاشة (موبايل)
  - شو بيصير إذا القائمة فاضية؟ أو إذا فشل الطلب؟
  - هل الشكل مزبوط بالعربي (RTL)؟
- قارن مع الصور الموجودة بالـ PR.

### 3. شيّك

اقرأ تبويب **Files changed** وعلّم:

- [ ] الـ CI أخضر
- [ ] بيعمل اللي مكتوب بالـ PR وبس، وصغير لدرجة بتفهمه
- [ ] الملفات بمجلد الـ feature الصح، وما في استيراد عميق `@/features/x/...`
- [ ] طلبات الـ API بس بمجلد `api/`، والـ endpoint موجود بـ [05 · عقد الـ API](05-api-contract.ar.md)
- [ ] ما في بيانات وهمية مستوردة بالمكونات، ولا روابط مكتوبة يدوياً
- [ ] في حالات التحميل والخطأ والقائمة الفاضية
- [ ] كلاسات بتدعم RTL (`ms-`، `pe-`، `text-start`…)، وما في inline styles ولا ألوان مباشرة
- [ ] ما في مكوّن موجود أصلاً بـ `shared/components/ui`
- [ ] ما في `.env` أو أسرار أو `console.log` منسي
- [ ] التوثيق متعدّل بالنسختين `.md` و`.ar.md` (إذا في)

### القرار

- كلو تمام: **Review changes ← Approve**.
- في شي غلط: **Request changes** مع تعليق واضح على السطر:
  > "القائمة ما بتعرض شي لما `data` فاضية، فينا نستخدم `EmptyState` هون؟"
- ملاحظة ذوقية صغيرة ومو مانعة: علّق ووافق، وابدأ التعليق بـ `nit:`.

لما تخلص، ارجع لفرعك: `git switch <your-branch>`.

## بعد الموافقة (صاحب الـ PR)

1. اكبس **Squash and merge** (العنوان بصيغة Conventional Commit، مثلاً `feat(matching): add partner card (#15)`).
2. **Delete branch**.
3. عندك: `git switch main && git pull`.

## آداب المراجعة

- علّق على الكود مو على الشخص. اسأل بدل ما تأمر.
- راجع بنفس اليوم إذا قدرت، الـ PR اللي ناطر بيوقّف زميلك.
- إذا الموضوع كبير، احكوا (مكالمة أو شات) بدل سلسلة تعليقات طويلة.
